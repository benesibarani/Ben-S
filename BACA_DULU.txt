 TUTORIAL PUTARAN 14 - MENU PRO TERBUKA WALAU DATABASE SUDAH PRO
 (PENAWAR: data akun dari server menjadi bukti PRO di dalam HP)
==============================================================================

 ============================================================================
  PUTARAN 14 - DATABASE SUDAH PRO, TETAPI MENU PRO MASIH TERKUNCI
  (3 Oktober 2026)
 ============================================================================

  Kejadian yang Bapak laporkan:
    "Akun Sales di atas nama BENEDICTUS sudah akun PRO (akun_pro = 1,
     pro_mulai terisi, pro_selesai terisi). Di aplikasi juga statusnya sudah
     akun PRO. Tapi ketika diklik, menu-menu akun PRO tidak bisa terbuka."

  SEBABNYA
  --------
  Aplikasi menyimpan hasil pemeriksaan PRO di dalam HP supaya kasir tetap
  jalan tanpa internet. Jawaban LAMA "belum boleh" (dari masa akun masih
  GRATIS / uji coba sudah habis) masih tersimpan, dan jawaban itu dipakai
  lebih dahulu daripada data akun terbaru dari server. Akibatnya menu PRO
  tetap terkunci walaupun database sudah PRO.

  PENAWARNYA (3 lapis, sudah dipasang pada putaran ini)
  -----------------------------------------------------
   1. DATA AKUN DARI SERVER MENJADI BUKTI PRO DI DALAM HP.
      Bila `akun_pro` = 1 pada data akun (hasil login / session_check),
      maka seluruh fitur PRO langsung dibolehkan - jawaban lama "belum boleh"
      tidak dipakai lagi. (lib/kasir_lokal.dart: proSesi)

   2. SETIAP KARTU MENU PRO YANG DITEKAN MEMERIKSA ULANG KE SERVER.
      Bila pemeriksaan di HP masih menjawab "belum boleh", aplikasi bertanya
      langsung ke server (session_check.php). Begitu server menyatakan PRO,
      kartu itu LANGSUNG TERBUKA (tidak perlu keluar aplikasi).
      (main.dart: RtsAkunSegar + _bolehPro)

   3. STATUS AKUN DIPERIKSA SAAT APLIKASI DIBUKA DAN KEMBALI DARI LATAR
      BELAKANG, serta melalui tombol SINKRON AKUN pada menu Sinkronisasi.
      Halaman Kasir / Peta juga diberi data akun yang paling baru supaya
      keadaannya sama dengan Beranda.

  YANG PERLU BAPAK LAKUKAN (WAJIB memasang aplikasi baru)
  -------------------------------------------------------
     A. Unggah berkas server pada paket (api/langganan_inti.php) ke
        public_html/api, lalu buka langganan_admin.php dan tekan
        PERBARUI DATABASE sekali.
     B. Ekstrak RTS_PANEL_PUTARAN_14.zip, jalankan
        .\LANGKAH1_PASANG_SEMUA.ps1, lalu flutter clean -> flutter pub get.
     C. Bangun + pasang ke HP:  flutter run -d CPH1937
        (INI YANG PALING PENTING: aplikasi di HP harus versi baru. Selama HP
         masih memakai aplikasi lama, perbaikannya belum ikut terpasang.)
     D. Di HP: buka aplikasi sekali (status diperiksa otomatis). Bila masih
        terkunci, buka Sinkronisasi -> SINKRON AKUN. Kartu Menu PRO akan
        terbuka tanpa memasang ulang aplikasi.

  CARA MEMASTIKAN APLIKASI DI HP SUDAH VERSI BARU
  ------------------------------------------------
     Buka Pengaturan -> lihat penanda kode aplikasi. Harus tertulis
     RTS-2026-10-03-15. Bila masih RTS-2026-10-03-13 atau lebih lama,
     berarti aplikasi baru belum terpasang di HP.

  Nomor versi naik menjadi 1.2.7 / kode 10 (pubspec.yaml.updated memuat
  version: 1.2.7+10). Pada halaman Versi Aplikasi di panel, isi:
  Versi 1.2.7, Kode 10, Wajib JANGAN -> PUBLIKASIKAN.

 TUTORIAL PUTARAN 13 - AKUN PRO LANGSUNG TERBUKA SESUDAH TOP UP
 (+ TOMBOL SINKRON AKUN PADA MENU SINKRONISASI)
==============================================================================

 ============================================================================
  PUTARAN 13 - AKUN PRO TERKUNCI SESUDAH TOP UP: SUDAH DIPERBAIKI
  (3 Oktober 2026)
 ============================================================================

  Keluhan Bapak:
    "Ketika user sales sudah top up dan ADMIN sudah setujui, status akun sales
     tetap terkunci untuk fitur PRO-nya."

  DUA SEBAB, KEDUANYA SUDAH DIPERBAIKI:

   1. DI APLIKASI - jawaban "belum boleh" disimpan terlalu lama.
      Aplikasi menyimpan hasil pemeriksaan PRO di dalam HP supaya kasir tetap
      jalan tanpa internet. Jawaban "belum boleh" (GRATIS) tadinya dianggap
      masih berlaku sampai 6 JAM, sehingga pembayaran yang sudah disetujui
      ADMIN tetap terkunci.
      SEKARANG: jawaban "belum boleh" hanya berlaku 3 MENIT, lalu aplikasi
      memeriksa ulang sendiri. Jawaban "boleh" tetap 6 jam (agar tetap jalan
      tanpa internet). Status juga diperiksa ulang setiap aplikasi dibuka dan
      setiap kembali dari latar belakang.

   2. DI SERVER - penanda akun_pro belum ada di database.
      Akun tadinya dianggap PRO hanya bila kolom `akun_pro` bernilai 1.
      SEKARANG: tanggal `pro_selesai` (tanggal berakhir langganan) SENDIRI
      sudah cukup untuk menjadikan akun PRO - jadi pembayaran yang sudah
      disetujui ADMIN langsung membuka fitur PRO.
      Perbaikannya ada di berkas  api/langganan_inti.php.

  FITUR BARU YANG BAPAK MINTA: menu Sinkronisasi kini memuat KARTU STATUS
  AKUN + TOMBOL "SINKRON AKUN" di bagian paling atas. Menekannya membuat
  aplikasi memeriksa ulang ke server (langganan + sesi + izin PRO di HP),
  lalu menampilkan hasilnya, misalnya:

      Status Akun                                     [ PRO / GRATIS ]
      Berlaku sampai 02-11-2026 (sisa 30 hari)
      [ SINKRON AKUN ]
      "Akun PRO AKTIF sampai 02-11-2026 (sisa 30 hari). Seluruh menu PRO
       sudah dapat dibuka."

  Tombol SINKRONKAN SEKARANG pada menu yang sama juga ikut menyegarkan status
  akun. Jadi sales yang sudah top up cukup menekan salah satu tombol itu
  (tanpa perlu memasang ulang aplikasi).

  LANGKAH PEMASANGAN (3 langkah):
     A. Unggah api/langganan_inti.php (dan berkas server lain pada paket) ke
        public_html/api, lalu buka langganan_admin.php dan tekan
        PERBARUI DATABASE SEKALI.
     B. Jalankan .\LANGKAH1_PASANG_SEMUA.ps1 dari paket RTS_PANEL_PUTARAN_13.zip,
        lalu  flutter clean  ->  flutter pub get.
     C. Di HP sales: menu Sinkronisasi -> tekan SINKRON AKUN.

  PENJELASAN LENGKAP: berkas MENU_LANGGANAN_PRO.txt, bagian
  "BAGIAN 0 - AKUN SALES MASIH TERKUNCI SESUDAH TOP UP".

  Nomor versi naik menjadi 1.2.6 / kode 9 (pubspec.yaml.updated memuat
  version: 1.2.6+9, penanda aplikasi RTS-2026-10-03-14). Pada halaman Versi
  Aplikasi di panel, isi: Versi 1.2.6, Kode 9, Wajib JANGAN -> PUBLIKASIKAN.

 TUTORIAL PUTARAN 12 - TIGA MENU PRO PETA (OpenStreetMap):
 PETA CUSTOMER, RADAR CUSTOMER, dan RUTE PLAN (+ PENSIL rute & SALIN plan)
==============================================================================

 ============================================================================
  PUTARAN 12 - TIGA MENU PRO PETA YANG SUDAH DIKERJAKAN (3 Oktober 2026)
 ============================================================================

  1. PETA CUSTOMER  - peta OpenStreetMap melampirkan SELURUH toko lengkap
     dengan titik-titiknya. Titik dapat DISARING menurut HARI kunjungan dan
     menurut FREKUENSI KUNJUNGAN (Weekly / Bi-Weekly Ganjil / Bi-Weekly
     Genap). Warna penanda dapat dipilih: menurut HARI atau menurut
     FREKUENSI. Ada pula legenda, pencarian nama/kode toko, tiga pilihan
     tampilan peta, jarak dari kantor, dan tombol KUNJUNGI.

  2. RADAR CUSTOMER - menampilkan DAFTAR customer di sekitar petugas, urut
     dari yang paling dekat, lengkap dengan JARAK. Tampilannya:
     Nama Toko, Alamat, Jarak (+ arah mata angin). Pilihan jarak maksimal:
     100 m, 250 m, 500 m, 1 km, 3 km, 5 km, atau Semua.

  3. RUTE PLAN      - membantu sales mendapatkan URUTAN TOKO dari jarak ke
     titik KANTOR, lengkap dengan filter warna. Ditambah dua permintaan
     Bapak:
        a. TOOLS PENSIL untuk membuat garis rute perjalanan di atas peta
           (5 warna, dapat dibatalkan, disimpan di HP, dan dimuat kembali).
        b. DAFTAR PLAN yang dapat DI-COPY PASTE berupa teks berisi
           NAMA CUSTOMER dan ID CUSTOMER (dua bentuk: LENGKAP dan
           NAMA & KODE), serta tombol BUKA RUTE ke Google Maps.

  ADMIN WAJIB MENITIKKAN LOKASI KANTOR / MITRA lebih dahulu, karena titik
  itulah yang menjadi awal perhitungan urutan rute. Caranya ada di dalam
  aplikasi: Menu PRO -> RUTE PLAN -> tombol GEDUNG -> tombol KANTOR ->
  AMBIL TITIK DARI LOKASI SAYA -> SIMPAN. Boleh lebih dari satu kantor.

  LANGKAH PALING PENTING (3 langkah):
     A. Unggah api/kantor.php ke public_html/api, lalu jalankan
        RTS_PANEL_KANTOR.sql di phpMyAdmin (tab SQL).
     B. Jalankan .\LANGKAH1_PASANG_SEMUA.ps1 dari paket
        RTS_PANEL_PUTARAN_12.zip -> skrip menyalin main.dart, lib\kasir.dart,
        lib\kasir_lokal.dart, lib\peta.dart, dan pubspec.yaml, lalu
        menjalankan flutter clean + flutter pub get.
     C. flutter run -d CPH1937, lalu titipkan titik KANTOR (lihat di atas).

  PENJELASAN LENGKAP + CARA UJI: berkas PETA_RADAR_RUTE.txt (9 bagian:
  peta, radar, rute, pensil, salin plan, lokasi kantor, daftar warna,

  Nomor versi naik menjadi 1.2.5 / kode 8 (pubspec.yaml.updated sudah memuat

  PUBLIKASIKAN.

  ============================================================================
   PERBAIKAN GALAT BUILD (3 Oktober 2026, penanda RTS-2026-10-03-13)
  ============================================================================

   Galat build yang berbunyi:

       lib/peta.dart:1636:65: Error: A value of type 'String' can't be
       assigned to a variable of type 'TextEditingController'.

   SUDAH DIPERBAIKI. Sebabnya satu baris pada lembar PENYARING PETA CUSTOMER:
   isi kotak pencarian tersimpan di _cari (jenis TextEditingController), tetapi
   ada baris onChanged yang mencoba menimpanya dengan teks biasa. Baris itu

   TERAPKAN ditekan. Bila Bapak memakai paket RTS_PANEL_PUTARAN_12.zip yang
   BARU (penanda RTS-2026-10-03-13), galat itu tidak muncul lagi.

   TIPS: sebelum membangun, jalankan perintah  flutter analyze  di folder
   proyek. Perintah itu memeriksa seluruh kode dalam hitungan detik (tidak
   perlu menunggu 3-4 menit) dan langsung menunjukkan baris yang bermasalah.

  ============================================================================
   TANDA MERAH DI VS CODE PADA main.dart (TIDAK BERBAHAYA)
  ============================================================================

   Bila VS Code menampilkan tanda merah seperti:

       Target of URI doesn't exist: 'kasir.dart'.
       Target of URI doesn't exist: 'kasir_lokal.dart'.
       Target of URI doesn't exist: 'peta.dart'.
       Undefined name 'RtsKasirLokal'.
       The method 'RtsPetaCustomerPage' isn't defined ...

   SEMUA itu datang dari berkas  D:\Project\rts_panel_app\main.dart  yang
   ada di AKAR folder proyek - yaitu SALINAN ACUAN dari paket, bukan berkas
   yang dibangun. Di dalam proyek ada DUA main.dart:

       main.dart       (akar)  -> salinan acuan; tiga baris import-nya tidak
                                  menemukan kasir.dart/kasir_lokal.dart/
                                  peta.dart karena ketiganya ada di lib\
       lib\main.dart   (lib)   -> INI YANG DIBANGUN FLUTTER, lengkap dan benar

   Jadi tanda merah itu TIDAK mempengaruhi hasil build. Supaya tidak
   mengganggu lagi, paket ini menyertakan berkas  analysis_options.yaml  yang
   menyuruh pemeriksa kode MELEWATI salinan akar tersebut. Setelah menjalankan
   LANGKAH1_PASANG_SEMUA.ps1 (yang memasang berkas itu), lakukan sekali:

       Di VS Code: Ctrl + Shift + P  ->  ketik  Dart: Restart Analysis Server

   Sesudah itu tanda merah palsu hilang, dan yang tersisa HANYA masalah yang
   sebenarnya (bila ada). Untuk memeriksa seluruh kode: jalankan
   .\PERIKSA_KODE_APLIKASI.ps1  (skrip itu ikut menjalankan flutter analyze).

  PENTING: pubspec.yaml menambah DUA paket baru (flutter_map dan latlong2).
  Keduanya 100% Dart - tidak ada kode Android/Gradle tambahan. Bila muncul
  pesan "requires Flutter SDK version ...", jalankan flutter upgrade lalu
  flutter pub get kembali.

 TUTORIAL PUTARAN 10 - KASIR OFFLINE (DATA DI DALAM HP) + IKLAN,
 LANGGANAN PRO (QRIS), DAN FOTO PRIBADI
==============================================================================

 ============================================================================
  PALING PENTING - BACA 6 BARIS INI DULU
 ============================================================================

  Sesudah permintaan Bapak tanggal 1 Oktober 2026, SELURUH data kasir
  (produk, stok, penjualan/nota, piutang, struk, dan template struk)
  sekarang DISIMPAN DI DALAM HP memakai database SQLite, sehingga KASIR
  TETAP BERJALAN WALAU TIDAK ADA INTERNET. Server hanya menyimpan daftar
  produk (SKU) beserta harganya.

  Yang perlu Bapak lakukan untuk perubahan ini:
     1. Jalankan .\LANGKAH1_PASANG_SEMUA.ps1 dari paket RTS_PANEL_PUTARAN_10.zip
        (skrip itu kini ikut menyalin berkas baru lib\kasir_lokal.dart)
     2. PERBAIKI_COMPILE_SDK.ps1 SEKALI SAJA - sudah dijalankan otomatis oleh
        LANGKAH1_PASANG_SEMUA.ps1 di atas. (Jalankan sendiri hanya bila
        pembangunan pertama Bapak belum memakai paket ini.) Skrip ini mengubah
        satu baris pada android\app\build.gradle.kts menjadi compileSdk = 37.
        Diperlukan karena paket permission_handler yang baru dibangun memakai
        Android SDK 37 (angka lebih tinggi selalu boleh - mundur kompatibel).
        Tanpa langkah ini, pembangunan dapat berhenti dengan pesan
        "permission_handler_android compiles against Android SDK 37".
     3. flutter clean  ->  flutter pub get  ->  flutter run -d CPH1937
     4. Uji: matikan internet HP, lalu buat satu nota. Harus tetap berhasil.
     5. Tekan CADANGKAN SEKARANG, lalu KIRIM berkasnya ke Google Drive.

  Penjelasan lengkap perubahan ini ada di berkas KASIR_BARANG_BAWAAN.txt
  (bagian 6 sampai 11). Tautan unduhnya ada di TAUTAN_UNDUH.txt.

  Bila Bapak ingin mengerjakan hal lain lebih dahulu (iklan, langganan PRO,
  dan foto pribadi), lanjutkan saja membaca berkas ini dari atas ke bawah -
  caranya tidak berubah.

  CATATAN PERBAIKAN GALAT (2 Oktober 2026):
     1. lib\kasir.dart sudah diperbaiki - nama pendek "ms" untuk pemindai
        kamera (tidak lagi bentrok dengan kelas Barcode paket printer) dan
        barcode nomor nota kini dikirim sebagai daftar karakter.
     2. PERBAIKI_COMPILE_SDK.ps1 sudah dijalankan otomatis oleh LANGKAH1
        (compileSdk 37), sehingga pesan permission_handler tidak lagi
        menghentikan pembangunan.
     3. Bila pernah muncul pesan "Expected to find ')'", artinya berkas
        lib\kasir.dart di komputer Bapak tidak lengkap (isinya ditempel
        sebagian). Jalankan .\PERIKSA_KODE_APLIKASI.ps1 untuk memeriksanya
        - skrip itu menunjukkan apakah kurungnya sudah berpasangan, tanpa
        perlu membangun aplikasi. Ukuran yang benar: 4.738 baris.
     4. Bila muncul pesan Kotlin "Redeclaration: class MainActivity" atau
        "Unresolved reference 'unaryPlus'": jalankan
        .\PERBAIKI_MAINACTIVITY.ps1 (sudah otomatis dijalankan oleh LANGKAH1
        pada paket PUTARAN_10 terbaru). Skrip itu memastikan hanya ada SATU
        berkas MainActivity.kt dan menaruhnya pada folder yang benar.

 PERTANYAAN YANG SERING DITANYAKAN
==============================================================================

   Apakah data customer saya terhapus?
     Tidak. Proses LANGKAH 2 hanya MENAMBAH kolom dan satu tabel baru.
     Data customer, pengajuan, dan stok tidak disentuh sama sekali.

   Bolehkah LANGKAH 1 dan 2 dikerjakan lebih dahulu, aplikasinya nanti?
     Boleh. Urutan paling aman memang server dulu, aplikasi kemudian.
     Aplikasi lama tetap dapat dipakai selama server diperbarui.

   Bolehkah LANGKAH 4 dikerjakan dua kali?
     Boleh, tidak apa-apa. Skrip selalu membuat cadangan lebih dahulu dan
     hasilnya sama.

   Bagaimana menyetujui pembayaran petugas dari HP?
     Masuk memakai akun ADMIN - buka Profil - Rencana Akun - tekan
     "KELOLA AKUN PRO (ADMIN)". Di sana ada daftar pembayaran yang menunggu
     (tombol SETUJUI / TOLAK) dan daftar seluruh akun (tombol +30 HARI,
     +90 HARI, TRIAL 7 HARI, HENTIKAN). Pemberitahuan pembayaran yang masuk
     ke HP Admin juga langsung membuka halaman ini bila ditekan.

   Apakah perlu unggah ulang berkas putaran sebelumnya?
     Tidak, kecuali belum pernah diunggah. Daftar berkas putaran sebelumnya
     ada pada NOTIFIKASI_OTOMATIS.txt.

   Apakah uji coba 7 hari langsung diberikan ke semua petugas?
     Ya, otomatis saat mereka masuk (login) pertama kali setelah
     LANGKAH 1 dan 2 selesai. Sekali saja untuk setiap akun.

   Bagaimana mengubah harga atau lama langganan?
     Buka api/langganan_inti.php pada hosting, ubah:
        rts_lg_harga()  -> 5000   (harga rupiah)
        rts_lg_durasi() -> 30     (lama PRO dalam hari)
        rts_lg_trial()  -> 7      (lama uji coba dalam hari)
